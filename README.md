# Async Job Processing API

Учебное API для фоновой обработки транзакций на FastAPI и asyncio. Приложение принимает данные транзакции, сохраняет задачу в SQLite и передаёт её воркерам через очередь. Клиент получает идентификатор задачи и отдельно запрашивает статус и результат.

Во время обработки параллельно выполняются три проверки: антифрод, оценка риска пользователя и оценка риска продавца. По их результатам формируется решение: `approve`, `review` или `reject`.

## Возможности

- Создание задач через REST API с ответом `202 Accepted`.
- Фоновая обработка тремя асинхронными воркерами.
- Конкурентное выполнение проверок через `asyncio.TaskGroup`.
- Общий семафор, ограничивающий число одновременных обращений к сервисам.
- Таймауты и повторные попытки при временных ошибках.
- Сохранение статусов, результатов и ошибок в SQLite.
- Валидация входных данных с Pydantic.
- Запуск и остановка воркеров через lifespan FastAPI.

Внешние сервисы имитируются задержками и случайными ошибками. Реальные платежи и обращения к антифрод-системам не выполняются.

## Стек

Python 3.11+, FastAPI, Pydantic, asyncio, aiosqlite, SQLite, Uvicorn.

## Установка и запуск

Откройте терминал в корне проекта и создайте виртуальное окружение:

```bash
python -m venv .venv
```

Активация на Linux / macOS:

```bash
source .venv/bin/activate
```

Активация в Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Установите зависимости:

```bash
python -m pip install fastapi "uvicorn[standard]" aiosqlite
```

Запустите приложение:

```bash
python -m uvicorn main:app --reload
```

Swagger UI: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

При запуске приложение подключается к файлу `jobs.db` в текущем рабочем каталоге. Таблица `jobs` создаётся автоматически, если её ещё нет.

## API

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `POST` | `/jobs` | Создать задачу и получить её идентификатор |
| `GET` | `/jobs/{job_id}` | Получить статус, исходную транзакцию, результат или ошибку |

### Создание задачи

```bash
curl -X POST http://127.0.0.1:8000/jobs \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": 10,
    "amount": 500,
    "currency": "USD",
    "merchant": {
      "id": 1,
      "name": "Demo Shop",
      "country": "US"
    }
  }'
```

Успешный ответ имеет код `202 Accepted` и содержит:

- `job_id` — UUID задачи;
- `status` — начальный статус `pending`;
- `created_at` — время создания;
- `links.status` — путь для получения статуса.

### Получение результата

Подставьте идентификатор из ответа вместо `JOB_ID`:

```bash
curl http://127.0.0.1:8000/jobs/JOB_ID
```

Ответ содержит данные транзакции, статус, время создания и обновления. После успешной обработки поле `result` содержит `fraud_score`, `user_risk`, `merchant_risk` и `decision`. При сбое задача получает статус `failed`, а описание ошибки сохраняется в поле `error`.

Если задача ещё обрабатывается, запросите её статус повторно через несколько секунд.

### Валидация

- `user_id` и `merchant.id` должны быть больше нуля.
- `amount` должен быть больше нуля и не превышать 1 000 000.
- Поддерживаются валюты `EUR`, `USD` и `GBP`.
- Название продавца должно содержать от 1 до 100 символов.
- Поле страны продавца должно содержать ровно два символа.

Некорректные входные данные возвращают `422`. Запрос задачи с корректным UUID, которого нет в БД, возвращает `404`.

## Обработка задачи

1. API сохраняет задачу со статусом `pending` и помещает её ID в `asyncio.Queue`.
2. Воркер получает ID и устанавливает статус `processing`.
3. Три проверки выполняются конкурентно с ограничением общей нагрузки.
4. Временная ошибка или таймаут запускает повторную попытку с увеличивающейся задержкой и случайной добавкой.
5. При успешных проверках результат сохраняется, а статус меняется на `completed`. При ошибке обработки — на `failed`.

Статус `completed` означает, что обработка завершилась успешно; решение при этом может быть как `approve`, так и `review` или `reject`.

### Правила принятия решения

| Условие | Решение |
| --- | --- |
| Антифрод-оценка ≥ 0.8 | `reject` |
| Оценка от 0.5 до 0.8 либо высокий риск пользователя или продавца | `review` |
| Оценка < 0.5 и оба риска не `high` | `approve` ||
